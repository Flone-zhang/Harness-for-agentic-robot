01 / OVERVIEW

Keep identity, state, and execution aligned.

Long-horizon manipulation requires task-state maintenance and verification of physical effects beyond continuous action generation. HarnessVLA coordinates subtask decomposition, dynamic memory, fact-validity checks, and monitoring around a fixed π0 executor.

Piper experiments cover blocks and a final button press, plus tube liquid transfer with substance identities, exchanged rack positions, and a supplied prohibited combination. Block success is 17/20 (85%) versus 3/20 (15%) for monolithic π0; A–B transfer reaches 34/40 (85%) versus 23/40 (57.5%) for full-instruction π0.

After short-term context reset, correct A–C refusal is 19/20 (95%) with persistent rule access and 0/20 without it. The rule-in-context reference reaches 20/20 (100%), and all three rule conditions have 0/20 false A–B refusals.

03 / METHOD

An explicit loop around the policy.

Only the execution layer drives the robot. The runtime grounds requested objects, checks supplied constraints, and advances only after evidence supports each physical effect.

  1. 01

    Decide

    Read persistent knowledge, current observations, and task state before choosing a call.

  2. 02

    Plan

    Generate ordered, object-bound calls with preconditions and completion predicates.

  3. 03

    Execute

    Invoke registered skills through the fixed π0 executor with a unique ID for each call.

  4. 04

    Verify

    Verify the specific physical effect before committing state or advancing.

Substance identity, scene position, and skill invocation.

A position swap changes the scene binding, while substance identity and the registered grasp skills stay stable.

OBJECT-BOUND CALLgrasp(position) → pour → discard_tube

A unique invocation ID keeps each tube’s completion evidence separate, even when skills are reused.

M

Persistent knowledge meets fresh scene state.

For tubes, Mₜ = {L, Eₜ, Tₜ, K}: L contains the supplied color map and prohibited pair; Eₜ holds current scene bindings; Tₜ tracks each tube’s stage; K stores skill definitions. Fresh observations invalidate obsolete positions.

W

Bounded recovery, explicit transitions.

Block execution uses bounded wait, end, replay, recovery, and suffix replanning. In the tube protocol, failed, uncertain, or exhausted calls stop downstream execution rather than committing an unverified effect.

04 / BLOCK AND BUTTON TASKS

The block benchmark and its task conditions.

T1

Sequential tidying

Move two blocks to their target containers and press the button. Tests multi-step composition and subtask switching.

T2

Context interruption

Pause T1, clear short-term agent context, and ask the agent to continue. Probes the role of persistent facts.

T3

Perturbation recovery

Introduce an empty grasp, a drop, a moved box, or an occlusion. Probes replay, recovery, and replanning.

Scope of the evidence

Block results are aggregated by configuration, without separate T1–T3 counts. The new tube rule-memory experiment below is a distinct context-reset test.

Independent component additions do not measure component interactions or the effect of removing a module from the complete system. Runtime cost, transfer to other robots, and paired statistical tests are not established by these counts.

Figures and demonstrations illustrate the mechanism. Aggregate outcomes do not provide per-trial timing or a measured failure distribution.

06 / TUBE EXPERIMENT

Transfer the right substances. Retain the supplied rule.

A four-position rack, one beaker, and a waste container form the second Piper task. A–B requests are allowed; A–C requests are prohibited by an explicitly supplied rule.

Six calls, with evidence for each tube.

Each requested tube is grasped, poured into the beaker, and discarded before the next grasp. The registry contains grasp1–grasp4, pour, and discard_tube.

Completion requires physical effects.

Both requested liquids must enter the beaker and both tubes must reach the waste container. The tested endpoint does not require stirring, a measured volume, or a chemical reaction.

A–B transfer: 85% versus 57.5%.

Both methods use the same π0 checkpoint, camera views, platform, and completion criteria. Each method is tested 20 times per arrangement: 40 trials per method, 80 in total.

After a context reset, access to the rule matters.

The same agent interface is tested under three rule-access conditions. Each condition has 20 A–C requests and 20 allowed A–B requests on the physical Piper platform.

Persistent access produces a 95-percentage-point correct-refusal difference after reset. Zero false A–B refusals in every condition indicates that the observed A–C refusals are not produced by rejecting all requests.

What these tube experiments establish

A–B success measures physical transfer and disposal; A–C refusal measures access to a supplied prohibition. These are separate outcomes and cannot be combined into one success rate.

The tested arrangement exchange concerns A, B, and slots 1–2. It does not establish four-position performance, autonomous tube recovery, chemical-compatibility inference, or cross-robot transfer.

Failure to refuse correctly does not by itself establish that a prohibited transfer occurred. The rule is supplied rather than autonomously learned, and aggregate counts do not determine failure categories or runtime cost.
