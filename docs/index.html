01 / OVERVIEW

Long tasks need a runtime that keeps track.

Vision-language-action policies translate language and images into continuous robot actions. Over long task sequences, execution remains vulnerable to accumulated errors, implicit subtask boundaries, and loss of task state.

HarnessVLA separates a fixed π0 executor from task decomposition, dynamic memory, typed skill invocation, and Watchdog monitoring. The agent assembles current observations, task state, registered tools, and validity-filtered persistent facts before each decision.

On the physical Piper robot, the complete system achieves 17/20 successful trials (85%), compared with 3/20 (15%) for monolithic π0. Independent component comparisons identify subtask decomposition as the largest observed isolated improvement.

03 / METHOD

An explicit loop around the policy.

Only the execution layer drives the robot. The surrounding harness manages the goal, state, skill contracts, and completion evidence.

  1. 01

    Decide

    Assemble observations and valid memory into the multimodal agent’s context.

  2. 02

    Plan

    Generate ordered subtasks with preconditions, completion predicates, and action budgets.

  3. 03

    Execute

    Invoke registered skills through typed interfaces using the fixed π0 executor.

  4. 04

    Verify

    Use Watchdog feedback to wait, end, replay, recover, or replan.

M

Dynamic memory, with fact validity.

Environment state Eₜ, task state Tₜ, the tool index Kₜ, and persistent facts Fₜ form the memory window. Fresh observations override contradictory state facts; only valid facts enter the next decision.

W

Bounded recovery, explicit transitions.

The Watchdog checks progress and completion evidence at a skill-specific frequency. Failed or stagnant execution triggers bounded retries or recovery; exhausted budgets lead to suffix replanning or failure.

04 / TASK SUITE

Planning, continuation, and recovery.

T1

Sequential tidying

Move two blocks to their target containers and press the button. Tests multi-step composition and subtask switching.

T2

Context interruption

Pause T1, clear short-term agent context, and ask the agent to continue. Probes the role of persistent facts.

T3

Perturbation recovery

Introduce an empty grasp, a drop, a moved box, or an occlusion. Probes replay, recovery, and replanning.

Scope of the evidence

The reported counts are aggregated at configuration level and are not broken down by T1, T2, or T3. They do not establish perturbation-specific recovery rates or interruption-specific continuation performance.

Independent component additions do not measure component interactions or the effect of removing a module from the complete system. Runtime cost, transfer to other robots, and paired statistical tests are not established by these counts.

The linked repository is the public implementation. Its current README describes T3 recovery as verified in the mock executor; that implementation scope should be distinguished from the manuscript’s task definitions and aggregate experimental results.
